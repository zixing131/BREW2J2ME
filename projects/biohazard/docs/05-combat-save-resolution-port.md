- 13 种原武器定义、32 个武器槽：伤害、射速、近远射程、瞄准角、装弹、弹匣、击退、硬直、效果索引、五项升级。

- 原物品拾取、恢复剂、弹药、金钱和剧情变量；六种普通商品扣款；超级商品使用原授予逻辑和限购记录。
- 三个手动 RMS 槽与独立自动槽；继续游戏读取记录，手动覆盖需要确认。保存失败不会显示成功；最近一份损坏时尝试上一份有效记录。
- 原脚本的发放武器/物品、保存提示、区域交互、换关确认、直接换关、商品提示、结束事件均接入。原资源中出现的全部 opcode 已有分支。
- 240×320、320×240、360×640，以及 176×220 / 640×360 的界面和触屏输入回归；运行中尺寸变化会重建视口、清除按键状态。
- 原墙面方向标志、盒体四个面、静态物品、敌人动画接入适配绘制器；修复医院“安静”贴图水平镜像。

## 逆向依据与容易读错的地方

| ARM 镜像地址 | Java 实现 | 恢复内容 |
|---|---|---|
| 0xD10 / 0x6254 / 0x12E0C | OriginalPlayer / OriginalData | 原武器 ID 查找、增加/移除槽 |
| 0x12F30 | OriginalData.resolve | 18 字节最终武器参数，已执行原 ARM 做差分 |
| 0x571C / 0x124A0 | OriginalData.upgradeCost | 逐级增长后累计价格，扣除已升级累计值 |
| 0x19868 / 0x19930 | OriginalMath | 原查表角度、整数平方根 |
| 0x576C / 0x58EC / 0x1098 | OriginalMath / OriginalCombat.aim | 两种视线测试、最近目标、中心判定 |
| 0x20458 | OriginalCombat | 玩家战斗、装弹、射击、命中、击退 |
| 0x20C54 / 0x1209C | OriginalCombat | 敌人状态、死亡回调、40 槽投射物池 |
| 0x19C88 / 0x1293C / 0x1ECE8 | OriginalPlayer | 药品、超级道具效果、消耗隐身次数 |
| 0x5E14 / 0x11B3C / 0x18B5C | OriginalPlayer / OriginalSession | 原存档字段、关卡与玩家状态 |
| 0x24FDC / 0x19C14 / 0x15BB8 | OriginalVM | 区域与指定事件、物品/保存/换关命令 |
| 0x2319C / 0x4F8C / 0x9990 | OriginalRenderer.textureU | 纹理转换与原面方向标志 |

15000 资源是 `u16 shopCount + 12×20 B + u16 weaponCount + 13×72 B`。武器定义始于 244，不能把同样是 72 字节的墙面运行时结构当成武器表。

每槽 8 字节：`ID, 定义索引, 伤害等级, 射程等级, 射速等级, 瞄准等级, 装弹等级, 当前弹匣`。0x12F30 的六个 u16 基值位于定义 +54..64；增量偏移 +4/+12/+20/+28/+36/+44，所用槽等级依次 +2/+4/+3/+3/+5/+6。末尾六个 byte 为：定义 +66、+67、**槽 +7**、定义 +68、+69、+70。不能简单复制定义 +66..71 后覆盖第三项，那会把击退、硬直和效果索引全部错位。520 组 ARM 结果覆盖所有 13 武器及不同升级组合。

敌人来自 51000 的 37×84 B 描述，关卡每个实例 20 B。实例的死亡事件在 byte16 / u16@18；击杀后等待硬直结束才进入死亡状态并触发 type3 事件。首次医院指定敌人连接原事件 2，实际集成测试验证变量 0 从 2 变成 3，不是自编的击杀数判胜。

区域原资源存的是 **x1,y1,x2,y2**。0x24FDC 先做右下角减左上角，再交给 0x19C14 判断；Java 直接比较 `x>x1 && y>=y1 && x<x2 && y<y2`。若误把后两个值直接当宽高，医院保存交互会扩大并阻挡射击。

“安静”修复：提取的 PNG 是常规像素布局，原 0x2319C 还会转置/反转，随后光栅器再应用面方向。Java 直接采样 PNG 时，raw flags bit0=0 应使用 `1-u`，bit0=1 使用 `u`。修复落在面采样，不改原图片、不把所有纹理统一镜像。预览使用用户截图同一镜头 **L1 (889,105,50)**。

## 存档

原 `save.dat` 为 **856 B**：8 B 头 + 788 B 玩家记录 + 60 B 全局记录。玩家记录相对偏移：

| 偏移 | 字段 |
|---|---|
| 0 / 2 / 4 / 6 | 关卡号 / x / y / 角度，16 位；0 是关卡号，不是保存次数 |
| 8 / 12 / 16 | 金钱 / HP / 备用弹药，32 位 |
| 20..519 | 500 个剧情/拾取变量 |
| 520 / 522 / 524 / 526 | 药品 / 当前武器槽 / 槽数 / 超级武器专用槽 |
| 528..783 | 32×8 B 武器槽 |
| 784..787 | 保存标志与三项教程标志 |

全局记录保留最大生命、购买计数、待处理计数、隐身次数、GPS、无限弹药、超级武器以及其余不透明字节。真实原存档导入后得到关卡1、(883,59,258)、$37、HP50、备用20、两武器槽；重新序列化与原文件逐字节相同。原文件始终只读。`fromBrew` / `brewSave` 提供格式转换；当前菜单读取本移植版 RMS，没有手机文件选择器。

J2ME 快照 `BIO3 / version1` 嵌入原856 B记录，再保存 VM 执行位置、动作帧、一次性事件标志、敌人状态、投射物、冷却/装弹/切枪、随机适配器状态、保存时间和序号，末尾 CRC32。**这是扩展行为**：原存档重建关卡，J2ME 存档能在对白或战斗中精确续接。

RMS 名为 `bio-original-v3-0..3`，0..2 为手动，3 为自动。每槽两个交替记录，写入后重新读取和解码才报告成功。暂停、进入主菜单、后台和正常退出尝试自动保存；死亡时不覆盖自动记录。强制终止进程没有回调时只能恢复上一次成功写入。旧演示 `SaveStore` 不复用。

## 商店和平台适配

普通商品来自原表/逻辑：恢复剂数量 1/2/6，价格 120/200/500；备用弹药 50/100/500，价格 100/150/650。恢复剂恢复最大生命 40%，最多到上限；原逻辑满血也消耗一份。超级武器填充原升级上限，替换专用槽。

原超级商店调用已停用的短信计费回调。本版明确显示 **OFFLINE / NO SMS**，确认后应用原效果，不发短信、不联网、不伪造真实付费。购买计数、限购、GPS、无限弹药、隐身次数、生命加成、金钱和武器记录均持久化。隐身次数在系统菜单消耗；原复活效果恢复满血并提供临时隐身。

BREW 随机服务用保存种子的确定性 LCG 适配，原概率/频率和范围逻辑保留；不宣称和某一次 BREW 运行的随机序列一致。逻辑 tick 为50ms；手机原墙钟速度仍需录像对照。

屏幕使用完整设备尺寸；360×640 采用2倍像素显示，其他尺寸按可用整数倍率布局。触屏时 HUD 高61逻辑像素、非触屏47；触控区域叠加在视口底部。菜单绘制与点击共用 ScreenLayout。MIDP 单指按住可移动/开火，拖动切换按键；不声称支持多点触控同时移动射击。设置菜单可关闭触控层。
