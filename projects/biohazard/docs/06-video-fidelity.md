# 原版视频对照与体验修正

参考：阿拉雷叔 [《3D生化启示录》求生（上）](https://www.bilibili.com/video/BV17e4y1V7wv)。
视频共 12:48，简介注明游戏画面从约 3:00 开始；包含剪辑和解说，并非连续按键输入记录。
已直接观察约 3:12 的医院、消防斧、绿色瞄准框、拾取提示、顶部武器栏、圆形雷达与左下四个快捷键。
用户登录后已恢复访问，并直接观察了约4:44的瑞克对话、7:44的医院对话、8:48的室外人声对话。参考帧放在忽略的 `.local/reference-video/`，不把他人的视频复制进仓库。以下时间是已观察片段，不表示逐秒看完。

## 相机与物体比例

此前 Java 渲染器采用通用的 `width / 1.32` 焦距、48 单位眼高，以及居中的视平线。
这些参数没有原程序依据，会改变视野、地面比例和敌人大小。

已从原程序确认：

- `0x17858`：眼高 210、焦距 170、垂直偏移 `200 - (viewHeight >> 1)`、远裁剪 1000。
- `0x4F8C`：地图坐标与墙高在投影前乘 4，因此 Java 地图单位下眼高是 52.5。
- 原生 176×173 世界视口的视平线为 77；焦距 170，而非此前的约 133。
- `0x21FB4`、`0x6640`：天花板高度取关卡头第 11 字节乘 32；地板与天花板到眼睛的距离不同。
- `0x48A0`、`0x9990`：精灵缩放使用描述符第 6 字节、到相机的径向距离以及独立锚点。
- `0x1E204`：开火动作的第 3 个 short 是相机沿朝向后移的距离，仅影响绘制，不修改玩家位置。

实际执行原 ARM `0x17858`（Unicorn）得到：

| 视口高 | 眼高 | 焦距 | 垂直偏移 | 远裁剪 |
| --- | --- | --- | --- | --- |
| 173 | 210 | 170 | 114 | 1000 |
| 193 | 210 | 170 | 104 | 1000 |
| 273 | 210 | 170 | 64 | 1000 |

进一步核对 `0x17200` 与随包 `biohazard.bin`：原作基准为 176×220，但会取实际屏幕尺寸自适配，且焦距仍为 170。不能把 240×320 的焦距再乘 240/176。
`OriginalCamera` 因此在逻辑视口保留固定焦距，额外分辨率显示更多场景；高分辨率的像素放大统一由 Canvas 做整数缩放。

## 原始界面资源驱动

`OriginalAnimation` 按 `0x193E0` 解析资源 20000 的 8 组动画，每帧包含 24 字节的控件记录。`0x1CE08` 规定底部居中锚点、独立 X/Y 百分比缩放和水平/垂直翻转。

- 动画 7 / 帧 0 包含两份封面 5045：顶部正常、下方垂直翻转。这解释了 240×320 截图里的倒影，并非需要补画背景。
- 动画 6 / 帧 0、1 恢复原主菜单和选中偏移（素材左移 13，文字左移 12），位置按 `0xEDD4`。
- 动画 3 恢复 HUD、原武器图标映射/缩放、四个快捷按钮；数值位置依据 `0x77C4`。雷达圆形裁切与旋转依据 `0xA7E8`。
- 图像 4301 / 4302 的三个状态恢复绿色/黄色/红色瞄准；宽度取武器瞄准角，锁定位置跟随敌人。
- 动画 1、2 恢复短代商场、超级枪械和随身商店。短代商场按 `0x1627C` 显示六个分类，超级枪械进入五种武器子菜单；不再把 12 条收费资源平铺成菜单。
- 商店显示行数、描述区、确认/返回和箭头采用 `0x8164`、`0xC144` 的布局。离线领取适配仍然保留，不发送收费短信。
- `0xD7A8` 的消防斧挥击缩放也已接入。

## 射击事件

Canvas 原先在每个 50ms 更新中重复调用 `fire()`，会把一次按住狙击键变成开镜后马上射击。现在只在新的按下事件请求射击；命中后连续攻击仍由原 `OriginalCombat.fireRequested` 状态机决定，不被适配层覆盖。新增生产 Canvas 回归验证一次长按仅开镜、第二次按下才射击。

同时按 `0xD7A8` 恢复开镜时半径80的黑色遮罩和原4304准镜图像；狙击枪未开镜时不绘制普通武器的括号准星。

## 材质与雷达

- `0x235F4` 的四方向线性、四角径向、四角反向蒙版已移植，保留 RGB565 整数截断、叠加贴图、局部阴影及整块半亮规则。
- 新的 `material_oracle.py` 实际执行该原 ARM 函数，只适配 malloc/free、memcpy 和资源查询；27张32×32结果作为独立期望，Java逐像素相等（27,648像素）。测试不使用Java结果生成期望。
- 按 `0x21FB4` 接入关卡雾色、雾起点和密度；灯光贴图7—10的常亮/闪烁标志来自 `0x6640`。墙和精灵的雾采样仍是Java深度计算，不能据材质一致推断整帧完全一致。
- 雷达增加原出口、区域目的地和剧情目标，坐标直接来自 ARM `0x270F0`、`0x27170`、`0x271B0`，204个分量与原数据逐项对照。标记使用原2102—2104图像；屏外半透明效果仍有差异。

## 验证结果与边界

### 0.3.3 对话与章节内容

视频4:44的锁门对白对应正文6040、姓名6020。`0x15BB8` / `0xF7D0` 确认：模式2在底部使用动画3帧3的金属面板、黄色姓名和头像；正文有姓名时高34、无姓名时高50，字符间距2、行距16。模式3使用居中小提示框。`0x10250` 支持方向滚动、确认翻页后结束。移植已恢复这些表现；176×220与视频对照，其他尺寸延展面板宽度以承载自适配正文。

头像选择依据姓名的首个UTF-16字符，常量分别为7001—7005，未知姓名不显示头像。不能把脚本word4直接当作图像ID：它在模式1/2中是姓名文本ID，在模式0中则是连续文本数量（`0xEE4` 上限10、0按1处理）。此前模式0只显示第一条资源，0.3.3恢复章节标题后续文本；该版本仍使用分页确认，逐字显示与自动推进在下述0.3.6中继续恢复。

生产Canvas测试增加五分辨率对白及末页、无姓名叙述、居中提示、章节内容截图；177项Canvas/RMS断言通过，原系统39,221项断言通过，原有ARM差分继续通过。实际绘制已人工查看原生分辨率的瑞克头像/锁门对白与章节标题。

### 0.3.4 室外背景与远处地面边界

视频上集8:48与[下集](https://www.bilibili.com/video/BV1SG4y1D7WA)约1:54可见深蓝星空、山脊背景。此前Java在没有天花板的关卡直接填灰，且无限远的地面采样覆盖了本应属于背景的区域。

`0x6E98` 依次消费关卡头后的16字节背景记录：类型2平铺1400，类型3按方向定位1401，类型1画RGB565渐变。六张室外地图保留原记录顺序；其中52007/52014的星空方向参数与其他四张不同，没有强制改成一致。`0x21FB4` 的地面/天花板远裁剪带决定背景可见范围，开镜使用双倍焦距重新计算。

`sky_oracle.py` 实际执行这两个ARM函数，只截获资源查询和绘图输出。覆盖3种关卡、5种视口、2种焦距、8种朝向，共240组；Java的上下裁剪带、图像ID、位置、尺寸、标志及颜色参数逐项相等。它证明背景命令一致，不等于整个画面的光栅化逐像素一致。另生成五分辨率医院出口室外截图供人工检查。

### 0.3.5 枪口遮罩

直接复核`0xD7A8`确认：枪口使用颜色图4101，配合效果记录`+12`周期和`+13...`列表选择4111—4115遮罩。只在非狙击、非禁用枪口、开火第0帧绘制，位置取效果记录`+8/+10`，在武器图之前混合；周期索引来自累计开火次数`engine+2136`。

此前资源提取器跳过flags=0x11，导致所有枪口透明度效果缺失。现已解析五张稀疏字节遮罩，保留0..32权重及RGB565整数混合。`flash_oracle.py`直接执行原`0x3324`，25组完整帧包含正常、左右、上下裁切；93,600像素逐项相等，包括原稀疏路径裁切偏移规则。生产Canvas也验证实际开火加载遮罩，生成开火/下一帧对照截图。

敌人动画索引另经汇编核对：`0xA3C8`调用除法后，`0xA3CC`使用R1余数；现有`ticks % period`正确，不能把反编译器遗漏的R1误当成R0商值改成除法。

### 0.3.6 旁白时序与兼容存档

模式0的实际游戏绘制入口为`0x1D170`，当前28条原剧情旁白均使用横排模式1：黑底、160像素文字区域、字间距8、行距20，并随已显示内容滚动。`0x20298`每4次更新调用`0xA10`推进一个字符或完整格式指令；资源结束追加换行，全部显示后等待18次更新结束。`0x101B4`的确认键推进10步，不直接关闭旁白。移植现已接入该状态机，取代分页确认。

`narration_oracle.py`无宿主回调地执行以上三个ARM函数，对章节两条文本、长段叙述、确认加速和格式指令共768帧，逐帧比较字符位置、时钟、结束等待和活动标志。生产Canvas验证不按确认也能结束旁白、确认只加速显示，并人工查看居中文字预览。50ms平台更新间隔沿用当前移植设置；这些测试证明逻辑帧时序，不证明真机墙钟速度与视频完全相同。

J2ME快照升级为版本2，增加旁白显示位置和计时状态；RMS存储名称、槽位和CRC双记录机制保持不变。保留版本1读取：`snapshot-v1.bin`由历史提交`c0553e5`的实际旧编码器生成，验证旧记录的金钱/时间/序号/剧情恢复；旧版未保存的逐字进度从当前旁白开头重新播放。版本2则测试保存前后逐字状态完全一致、继续40步仍一致。

原 ARM 逻辑差分测试与 Java 渲染截图是两种不同证据。桌面 Canvas 测试运行生产绘制和输入代码，但使用 MIDP/RMS 适配器，不能代替真机性能测试。
通过五分辨率菜单/世界/商店截图与生产Canvas输入测试；240×320、320×240触摸默认关闭，360×640默认开启的规则未改变。原有存档、战斗、剧情和16关加载测试继续通过。0.3.6 JAR经过ProGuard CLDC预校验；最终系统断言144,860项、生产Canvas/RMS断言294项通过，其中大部分系统断言是ARM输出的逐像素/逐字段比较。

另启动KEmulator 2.22加载该JAR，日志确认新类、MIDlet入口和界面资源加载；宿主JInput依然提示缺少ARM64动态库，随后MIDlet继续运行。日志保存于`j2me/build/kemulator-0.3.6.log`。当前电脑控制接口未能绑定该Java窗口，所以本轮模拟器验证止于启动日志，不能写成逐键打通；截图验证来自生产Canvas桌面适配器。

### 0.3.7 物品名称、教学提示与虚拟键盘

针对用户反馈，直接核对原程序而非从截图补写提示：

- `0x9990`的场景对象分支读取36字节描述符：`+30`仅控制精灵隐藏，`+31==1`控制文字，`+32`是文本ID。此前Java在`+30!=0`时整项跳过，而且没有文字绘制入口，因此普通物品和只有名称的门都缺字。现已分别接入：消防斧6000、楼梯大门6001、子弹6071、生命药水6072等直接使用原资源与颜色/描边。
- 原名称按投影X居中，Y在视平线减半个字高，不按精灵顶部缩放。`0x48A0`的描述符`+28/+29`剧情隐藏条件和物品拾取变量也接入，消防斧获得后不再残留名称。Java通过深度缓冲遮挡文字；这仍是光栅适配，并非原绘制链的全帧逐像素复刻。
- `0x1B614`：首次子弹/药水分别显示6305/6302并记录教学标志，再次显示8960/8961。`0x24FDC`读取区域头`+10`的提示ID，仅进入区域时触发；`0x19C88`用药显示8000/8001。此前拾取只更新数量和标志，Canvas的用药字符串也没有世界绘制路径，现接入滚动提示。
- `0xE00`、`0x20228`：提示从屏幕宽度3/4处开始，每逻辑帧左移4像素，文字右端越过宽度1/4后关闭，不暂停战斗。`0x1D040`在原逻辑坐标50—70绘制提示带，RGB565颜色0x41c7、19/32混合、边线0x8cb3。触屏模式随增加的HUD高度下移。
- 原脚本本来保留6300/6301两段地图教学；输入曾依赖上一帧paint留下的页数，快速确认可能错误结束长段文字。现在每次确认前重新计算当前对白分页。帮助菜单改用7009原中文说明，支持2/8翻页。
- `ScreenLayout.defaultTouch`的QVGA关闭规则原本存在；这次修正设置入口直接翻转开关的行为。进入“游戏设置”只显示页面，选择“屏幕按键”才切换；“自动设置”恢复按实际Canvas分辨率决定，240×320及320×240关闭，360×640开启。手动选择仍在本次运行内优先。

`notice_oracle.py`只适配BREW的GetAppInstance，实际执行原ARM滚动/释放函数，25组输入共4,471帧的位置及活动状态与Java一致。测试覆盖原医院药水/子弹首次与重复拾取、教学标志存档恢复、区域提示不反复重启，以及通过生产Canvas确认键走完两段开场教学到存档点。五分辨率、原战斗/存档回归通过：系统153,814项，Canvas/RMS 324项；这些统计包含大量逐字段/逐像素断言。

人工检查生产Canvas预览中的消防斧和子弹名称、顶部滚动教学、开场教学分页、240×320设置页无键盘；预览在忽略的`j2me/build/ui-previews/`。0.3.7 JAR为546,921字节，经CLDC预校验并检查StackMap及JAD大小。此次未进行手机实机测试。存档布局未改变，已学教学标志继续沿用，旧存档不会强制重播首次拾取教学；滚动中的临时文字不写入存档。

目前仍须继续核对世界内弹道/命中特效、音效、部分系统界面以及全流程节奏。视频登录阻挡已解除，但尚未逐段完成全部对照，不能据这些修正宣称体验已经完全一致。
