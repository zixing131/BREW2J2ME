# 原版音乐与战斗特效恢复

## 0.3.9：音乐

证据来自原 ARM 导出，均位于 `reverse/decompiled/`：

- `00017790.c` → `0x24C64`：菜单选择资源 30000。
- `00017200.c` → `0x24C64`：游戏选择资源 30001。
- `000199ac.c`：释放前一播放器，加载指定资源，音量 100。
- `0001997c.c` / `000213a4.c`：播放结束清除播放标志，后续更新重新启动。
- `0001403c.c`：挂起时停止，恢复后重新进入当前音乐播放流程。

J2ME 使用 MMAPI 播放提取出的两段原 MIDI，循环次数 -1；切换菜单/游戏释放旧播放器；进入后台和退出时释放播放器与流。设置增加“游戏音乐”，独立 RMS 保存开关，避免改变旧游戏存档。设备不支持 MIDI 时游戏仍可运行，不在每帧反复创建失败的播放器。

目前资源中只有这两段 MIDI，已检查的开火、换弹、拾取路径没有独立声音调用。0.3.9只恢复这两段原曲；0.3.10按用户后续要求另加有许可的枪声和丧尸声音，明确区分原版资源与补充音效。

验证包含实际 MIDI 文件头、播放器切换/循环/挂起/恢复/关闭、设置持久化与失败路径；桌面 MMAPI 适配器只验证调用生命周期，不代表真机已发声。完整构建执行 CLDC 预校验。

快照升级至3，在原版本2尾部追加40个投射物类型和100条弹道状态。旧版1/2仍可载入；旧存档缺失的在途投射物类型无法可靠推断，读入为不可见，之后新生成的投射物恢复外观。`snapshot-v2.bin`是在升级前由真实版本2编码器生成的兼容性fixture。

## 补充声音与空间衰减

来源：

- [Gunshot Sounds](https://opengameart.org/content/gunshot-sounds)，Tabasco / Vincent Sevedge。网页标CC0，下载包内`creativecommons.txt`写CC BY 3.0；本项目按包内较严格的署名要求处理，记录作者、许可链接及改动。
- [Zombies Sound Pack](https://opengameart.org/content/zombies-sound-pack)，artisticdude，为Summoning Wars创作，CC0。

从原文件裁出4种枪声、3种丧尸声音；降低增益、滤波、短淡入淡出，转为11025 Hz单声道PCM16，合计87,358字节。原文件名和输入/输出SHA256在`j2me/assets/sfx/manifest.json`；[许可及署名](../j2me/assets/sfx/LICENSE.txt)随JAR打包。普通构建完全离线，直接复制已跟踪素材；需要重制时使用`tools/prepare_sfx.py`。

声音属于新增适配：枪械按手枪/步枪/霰弹枪/狙击四类映射，超级枪复用相近类别；消防斧不发枪声，开镜与空弹匣也不触发。敌人激活/攻击、受击、死亡产生独立声音通知；通知消费后清除，不存档重放。

两个WAV声道分别保留枪声和敌人声音，避免互相打断。敌人听觉范围240地图单位，32单位内音量85；之后按`85 × ((240-d)/208)²`衰减，128单位音量24，192单位音量4，超界0。每个更新帧根据当前玩家和发声敌人的坐标调整VolumeControl；原碰撞视线被墙挡住时静音，重新可见后恢复。相同种类事件优先最近敌人；普通叫声至少间隔20帧，死亡或音量高出当前12以上的更近敌人可以接管。这里只实现距离、遮挡与优先级，不依赖手机未必提供的立体声方位接口。

“游戏音乐”和“战斗音效”独立保存开关。暂停/后台/退出时释放音效播放器；进入暂停的当帧声音可能被截断，这是停止游戏声音的明确取舍。音频设备失败不会阻断游戏或每帧反复重试，手动重新开启可重试。

## 本轮验证

- `python3 tools/project.py test biohazard`：8项Python测试、155,368项核心断言、37,947项生产Canvas/RMS断言、33项音频生命周期与空间衰减断言。
- 240×320、320×240、360×640逐个检查命中四阶段、两类投射物、三帧弹道和受伤红屏；预览在`j2me/build/ui-previews/combat-*.png`。低分辨率不显示虚拟键盘，360×640保留触控，红屏不染HUD。
- 空间声音回归覆盖声源移动、听者移动、超出范围、墙遮挡/解除和更近敌人优先；检查同一次播放只改音量、不重复重播。
- `tests/device/AudioDeviceProbe.java`在KEmulator 2.22中实际运行：2 MIDI + 7 WAV均成功进入Player.STARTED，9/9；日志`build/audio-device-probe.log`。两个MIDI报告时长约168.428和28.241秒。这个探针不属于发布JAR。
- 发布JAR启动日志`build/kemulator-0.3.10.log`确认真实入口及菜单MIDI加载。宿主JInput仍缺ARM64动态库，模拟器继续运行；不把启动日志和桌面预览当完整人工通关。
- JAR/JAD字节数、class major45、新增音频/特效类CLDC StackMap、七个WAV与许可文件打包一致性检查通过。

仍需完整16关逐步录像对照、角色脚下阴影等细节和真机内存/帧率/混音兼容性验证。
