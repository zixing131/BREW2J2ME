# 0.3.0：开场战斗任务闭环

本轮把开场的“只能看剧情”推进为可操作的调查、战斗、保护任务与后续剧情。范围截至剧情11后的斯顿雪域场景，不等于整款游戏的所有关卡、职业、任务和物品系统已恢复。

## 数据与原生依据

- `0x2b750`：FIE编号取角色的field；DS编号为`field*100+stage`。剧情4的出口为`[41,2,11,5,256,205,5,0,0,4]`，故加载`41.fie`与`4102.ds`，不能直接把next=5当成自动剧情跳转。
- `0x28258`：DS按八个带u8数量的数组顺序读取。文件里的记录宽度依次为2、8、8、5、7、6、6、15字节；不是反编译内存结构的大小。`SceneData`保留全部字段，对全部716份原DS检查边界与EOF。
- `0x4f018`：type2区域中按确认，参数减100得到NPC编号。`4102.ds`的矩形`(176,175)-(247,190)`、参数130对应NPC30。`npcInfo`的field41/stage2条目明确关联任务0；原`quest`记录0名为“研究日志”，两个SC入口为0/1。`4102.sc`对应两句自述已译成中文。
- `4103.ds`：六个monster4，ACT11800/family0，坐标直接取原记录。`4104.ds`：七个monster144，同一ACT。`6.bd`头部4字节后每条145字节，ID从1开始。monster4为3级、HP41、攻击动作31、原攻击数值7；monster144为40级、HP4325、原攻击数值191。加载映射见`0x844d0`，文件record+50是u32 HP，攻击表从+78开始，每项15字节。
- `0x7fe9c`/`0x7638c`：攻击使用ACT帧的region和目标bounds。地面Y差用前后景深判定；局部高度框不重复叠加地面Y。朝向翻转水平边界，boundsKind=2不可被击中。保留ACT的boundsKind/regionKind，不能只保存有无框。
- `0x8a400`：HP降至0后播放动作19，死亡动画结束才从存活集合移除并检查清场。`0x800e4`在packed状态`0x3290b`清场触发ANI6；`0x4290b`清场完成任务463并触发ANI8。
- `0x76940`：上述两个教学状态免受玩家生命扣除；`0x859cc`在这两段跳过掉落。本版遵守免伤与不生成战利品，仍显示被攻击的反馈。
- ANI6→ANI7；ANI7的exitType3进入41/4并启动任务463。`0x346d0`把玩家改为ACT1/family1、等级60、职业5（德林），不是继续使用巴隆。`quest[463]`原文明确要求操纵德林保护二人三分钟。任务说明确认后才开始计时。计时结束分支`0x3a8f4`与清场分支都进入ANI8；因此提前消灭所有敌人也可完成，与原生分支一致。
- `0x346d0`的技能表前两项为31、35，对应动作58、61。相关效果按`0x7adf0`的资源映射使用30058、33061、32061。巴隆的上挑动作23、鬼斩动作24及30024效果；原基础攻击20/21/22连段使用100.bd的80/90/100基础值。技能表解析保留原42字节rank记录中的消耗、冷却与基础威力。
- `0x7e3ec`在保护战直接放行前九个技能槽，因此本版该阶段已接入的技能不扣MP、不加冷却。普通状态使用技能消耗；100ms冷却单位仍属于待实机校准的适配。

## 可玩流程与存档

标题四槽→100/101/102/103/999/201/3/4→研究室调查→在书桌区域按5确认两段原SC自述→ANI5→六名研究员战斗→ANI6/7→德林保护战→ANI8/9/10/11→斯顿雪域79/1。

这里的“任务0确认后进入ANI5”是依据NPC表、SC文本与相邻关卡数据接通的开场适配；原任务窗口的全部SC opcode/接受/完成处理尚未逐分支移植，不能把此链路称为原任务解释器已完整复刻。后续城镇区域仍只显示真实场景与实体，未开放无法验证的任务链跳转。

场景按实体脚底Y排序绘制原道具、人物、敌人与技能效果。普通攻击、三段连击、上挑、鬼斩均有ACT判定、命中反馈、原声音、死亡动画。德林接入两个原绑定技能和前后效果层；没有把巴隆的两个技能冒充成德林技能。数字1/3与对应触屏按钮释放技能，5攻击/交互，0或软键打开任务与保存菜单。巴隆`*`也为上挑。双击水平键进入原动作3冲刺，300ms按键窗口和移动步长仍为适配值。

四槽新增`DNB1`记录：场景/任务、玩家位置、HP/MP、当前动作与帧、连击覆盖、技能效果状态与位置、各敌人HP/位置/死亡/动作/本次攻击命中标记、随机种子、冷却、保护时间、当前SC分页、背景音乐及校验。恢复先构建隔离Session；校验失败不更改当前战斗。暂停、失焦、正常退出和关卡进入保存，暂停/对白不消耗保护时间。活动场景使用实际经过时间计时，避免低帧率拉长保护任务。旧DNS1/DNS2仍可读；旧剧情4/5/7/11结束记录迁移进入对应场景。

240×320、320×240默认没有虚拟按键；360×640、640×360默认显示两行控制条。HUD、任务提示、确认窗口与暂停菜单使用设备中文字体。开发浏览Session保持独立，正常战斗不再调用动作浏览器。

## 验证与边界

- Unicorn直接执行原ARM `0x7638c`，512组位置/攻击框/目标框与Java完全一致。基线与输入binary哈希提交在`tests/fixtures/hitbox-arm.csv`、`combat-provenance.json`。显式再生成工具为`tools/reverse/combat_oracle.py`。
- 全716 DS读取；研究室19个原道具、六研究员、七教徒、实际出生点与HP/动作字段核验；从实际出生点通过普通移动/攻击输入完成首波，无修改敌人HP、无瞬移的清场测试。
- 原死亡动画完成后才触发ANI6；上挑与30024鬼斩的真实攻击框命中；德林动作58/61及效果中途读档；三分钟任务计时、教学免伤、损坏记录拒绝、读档后逐tick结果一致。
- 生产Canvas在四种分辨率覆盖ANI5→战斗、ANI7→德林、计时→ANI8/9/10/11→雪域，键盘/触屏默认值、战斗RMS、音乐恢复与暂停界面，并输出截图。

仍需恢复：完整装备/属性/暴击/被动伤害分支，原AI加权游走与技能/召唤分派，空中浮空/位移/受击硬直完整状态，德林其余技能与多段伤害事件，技能升级/全部资源消耗规则，物品/掉落/经验、城镇NPC完整SC解释、通用ZON/地图解锁与任务条件图。当前基础伤害只实现原基础威力与防御减伤分支，HP/MP初始上限仍为100的适配值，不可宣称数值平衡已与原版完全一致。动画和效果使用原资源，但尚未做整场原版逐帧视频比对。
